1. Prepara el laboratorio

Necesitas Docker Desktop, Git y una cuenta de GitHub.

Crea tu propio repositorio

  1. Descomprime el ZIP que te entregó el docente. Si no tienes Git, instala Git para Windows ↗. Abre New repository en GitHub ↗.
  2. Ponle un nombre propio, elige Public y deja sin marcar README, .gitignore y License. Pulsa Create repository.
  3. Abre PowerShell en la carpeta descomprimida donde está compose.yaml. Ejecuta estos tres comandos:
git init -b main
git add .
git commit -m "Inicio del laboratorio"

En la página de tu repositorio vacío, copia el comando git remote add origin ... que muestra GitHub y ejecútalo. Después ejecuta:

git push -u origin main

Si GitHub pide iniciar sesión, hazlo. Al recargar tu repositorio debes ver Jenkinsfile, app/ y compose.yaml.

Si Git pide tu nombre y correo

Configúralos en Git con git config --global user.name "Tu nombre" y git config --global user.email "tu-correo". Repite el commit.

Git guarda versiones; GitHub guarda tu copia en línea. La carpeta secrets/ está excluida y nunca debe subirse.

Inicia los servicios

En la carpeta descomprimida, haz doble clic en INICIAR-AQUI.cmd. No crees los secretos a mano: el archivo los genera automáticamente la primera vez. Espera «Laboratorio listo» y mira en esa ventana las claves de Grafana y Kibana.

Si usas la terminal, ábrela en esa carpeta (donde está compose.yaml), no en C:\WINDOWS\System32. Ejecuta:

.\iniciar-y-verificar.ps1
docker compose ps -a

Debes ver seis servicios en Running y security_setup en Exited (0). El inicio genera las contraseñas y las muestra en la terminal; guárdalas en privado.

2. Prometheus: revisa métricas

Una métrica es un número que se mide con el tiempo.

¿Está disponible el servicio?

  1. Abre Prometheus → Status → Targets.
  2. Busca prometheus y flask_service.
  3. Comprueba que ambos estén en UP.

UP significa que Prometheus recibe métricas. Si está DOWN, revisa el servicio, la dirección y el puerto.

Consulta el estado

  1. Abre Graph, escribe up y pulsa Execute.
  2. Lee el resultado: 1 = UP, 0 = DOWN.
  3. Abre la pestaña Graph y prueba 5 minutos o 1 hora.
up

Para ver solo la app o contar los targets UP:

up{job="flask_service"}
count(up == 1)

Genera peticiones

  1. Consulta http_requests_total.
  2. Abre la aplicación varias veces.
  3. Repite la consulta. El valor debería subir.
http_requests_total
Abrir la aplicación ↗

Este contador suma peticiones. Si usas otra app, la métrica puede tener otro nombre.

3. Grafana: crea un panel

Grafana muestra las métricas en gráficos.

Conecta Prometheus

  1. Entra a Grafana. Usuario: admin. Usa la clave que mostró la terminal al iniciar.
  2. Ve a Connections → Data sources (o Configuration → Data sources).
  3. Elige Add data source → Prometheus.
  4. Escribe esta URL y pulsa Save & test.
http://prometheus:9090

Debes ver «Data source is working». Dentro de Docker se usa prometheus, no localhost.

Guarda el primer panel

  1. Crea un Dashboard → Add new panel y elige Prometheus.
  2. Abajo, pulsa Code, escribe up y pulsa Run queries. Debe aparecer una línea con valor 1.
  3. Título: Estado de los servicios (up).
  4. Pulsa Save dashboard (arriba a la derecha) y ponle Monitorización básica. En otras versiones, primero pulsa Apply.

Añade un gráfico de peticiones

  1. Añade otro panel. Pulsa Code y escribe la consulta siguiente.
  2. Pulsa Run queries y elige Time series.
  3. Título: Tasa de peticiones HTTP (5 min). Guarda el dashboard.
rate(http_requests_total[5m])

rate muestra el promedio de peticiones por segundo en 5 minutos.

4. Kibana: busca logs

Un log es el registro de algo que ocurrió.

Crea una vista de datos

Inicia sesión como alumno con la clave que mostró la terminal. Abre la aplicación una vez para generar un log y espera unos segundos. No necesitas Add integrations: Logstash ya envía los logs a Elasticsearch.

  1. Ve a Stack Management → Data Views (o Index Patterns).
  2. Pulsa Create data view.
  3. Nombre: logstash-*. Campo de tiempo: @timestamp. Guarda.

El asterisco incluye todos los índices que comienzan con logstash-. Si no aparece, abre la app otra vez y pulsa Refresh.

Busca un error

  1. Abre el enlace de error de prueba. La respuesta HTTP 500 es intencional.
  2. En Kibana abre Discover y elige logstash-*.
  3. Elige Last 15 minutes y busca level: "ERROR".
  4. Abre el evento. Lee la hora y el mensaje.
Generar error de prueba ↗
level: "ERROR"

Si no aparece, amplía el tiempo y comprueba que los logs estén llegando.

Gráfico de logs (opcional)

En Visualize Library → Create visualization, elige Lens y selecciona logstash-*. Usa barras o área: @timestamp en X y Count en Y. Guarda como Logs por intervalo de tiempo.

5. Seguridad en la práctica

Observa cómo se protegen los datos del laboratorio.

Revisa estas tres decisiones

  1. Acceso: Elasticsearch pide contraseña y Kibana usa una cuenta de alumno.
  2. Secretos: las claves se crean en secrets/. No compartas esa carpeta ni fotos de la terminal con claves.
  3. Alcance: las páginas se abren solo desde este computador (localhost).

DevSecOps: un servicio en UP también necesita controles de acceso. Revisa los logs sin escribir contraseñas en ellos.

6. Jenkins con GitHub (opcional)

Puedes continuar con una entrega simulada. Jenkins se inicia dentro del mismo Docker Compose.

¿Qué vas a publicar?

Jenkins descarga tu repositorio, revisa la app y publica el texto de app/home.txt. La aplicación muestra ese texto en http://localhost:8000; Prometheus y Kibana siguen observándola.

El botón solo abre esta ayuda. Jenkins se inicia con el archivo del siguiente paso. No necesita instalarse aparte en Windows.

Inicia Jenkins

  1. Termina primero el inicio normal del laboratorio y deja Docker Desktop abierto.
  2. En la carpeta del kit, haz doble clic en INICIAR-JENKINS.cmd. Espera «Jenkins listo»; la primera descarga puede tardar.
  3. Se abrirá Jenkins ↗. Copia la clave inicial que muestra la ventana del iniciador y desbloquéalo.
  4. Elige Install suggested plugins y crea tu usuario de Jenkins.

No compartas la clave inicial ni fotos de la terminal.

Conecta tu repositorio

  1. En Jenkins pulsa New Item, escribe laboratorio-devsecops, elige Pipeline y pulsa OK.
  2. En Pipeline, cambia Definition a Pipeline script from SCM y elige Git.
  3. En tu repositorio de GitHub, pulsa Code → HTTPS. Copia su URL terminada en .git y pégala en Repository URL. Si tu repo es público, deja Credentials: none.
  4. En Branch Specifier escribe */main. En Script Path escribe Jenkinsfile. Pulsa Save → Build Now.

Usa la URL de tu propio repositorio. El código se descarga dentro de Jenkins; ya no necesitas indicar una ruta de Windows.

Comprueba las 5 etapas

  1. Descargar de GitHub: muestra el commit usado.
  2. Validar cambio: comprueba el código y que app/home.txt tenga contenido.
  3. Publicar en la app: copia ese texto al volumen compartido.
  4. Verificar monitoreo: comprueba el mensaje publicado, Kibana y los targets UP.
  5. Verificar seguridad: comprueba que Elasticsearch niegue el acceso sin clave.

Si todas están verdes, abre la app ↗ y lee el mensaje.

Prueba un cambio propio

En tu GitHub abre app/home.txt, pulsa el lápiz, cambia el mensaje y confirma con Commit changes. Vuelve a Jenkins y pulsa Build Now. Recarga la app: debe mostrar tu nuevo texto.

Si Jenkins falla

Abre la ejecución → Console Output. Comprueba la URL de tu repositorio, la rama */main y el archivo Jenkinsfile. Para ver el contenedor, en la carpeta del kit ejecuta docker compose --profile jenkins logs --tail=80 jenkins.

Jenkins no tiene acceso al motor Docker. Solo publica el archivo de ejemplo en un volumen compartido.
